# Contract document template

Write this only when issues that run in parallel meet at a seam. Save it on the **project** (`save_document`,
`project: <project>`, title `Contract`). Keep it short and exact: sessions that never saw the conversation code against
it. Delete sections that don't apply.

The example values come from the meal import feature (MEA-11 → MEA-12..17), to show the level of detail that's
enough.

---

```markdown
# Contract

**Status:** draft | agreed | changed (see change log)

## Issues and what they use

| Issue | Scope (one line) | Uses | Owns |
|---|---|---|---|
| MEA-12 | meal_imports table + RLS + Realtime | defines DB-1 | `supabase/migrations/`, `supabase/tests/database/` |
| MEA-13 | ScrapeRecipe Function | DB-1, JSON-1, HTTP-1 | `MealWiz/src/MealWiz.Functions/` |

| MEA-15 | UI | API-1 (fakes it in bUnit until MEA-14 lands) | `Features/MealImport/ImportMeal/` |

**Shared files** more than one issue edits, with the owner of each edit, e.g.
`MealWiz/MauiWASM/ServiceCollectionExtensions.cs`: MEA-14 adds the registrations. `docs/agents/FEATURES.md`: each
issue adds its own rows to the MealImport section.

## Naming

- The feature's name in code, folders and UI text, matching the app (S-01): **Meal import** (`Features/MealImport`,
  `MealImport*`), not "Recipe". A late rename forces every other issue to follow.

## Items

### DB-1: `public.meal_imports`

| Column | Type | Notes |
|---|---|---|
| id | uuid PK | generated by the client before insert |
| created_by | uuid | `auth.uid()` |
| status | text | `pending` \| `succeeded` \| `failed` |

RLS: owner can SELECT and INSERT (status must be `pending`); owner can UPDATE `pending` → `failed` only.
Realtime: in the `supabase_realtime` publication.

### JSON-1: `meal_imports.parsed_meal`

`{ "Name": string, "Recipe": string, "Ingredients": [{ "Name": string, "Amount": string }] }`, PascalCase.
Duplicated in Functions and Shared, so it changes in both and in `MealWiz/tests/Contracts/` (FN-01).

### HTTP-1: `POST /api/ScrapeRecipe`

Body `{ "jobId": uuid, "url": string }`, header `x-functions-key`. `400` bad body; `200` the row holds the outcome;
`502` the row couldn't be reached (the client marks it failed). The response is an ack; the row is the truth.

### CFG-1: client config `MealImportFunction: { url, key }`

In every `appsettings.*.json`. Development url `http://localhost:7071`. The production key is injected by
`deploy.yml`, never committed (SEC-01).

### API-1: `IMealImportStateContainer` (used by the UI)

Each member the consumer may use, one line of behaviour each: `StartImport(url) → Result`, `JobStatus`,
`OnStateChanged`, threading notes.

## Decisions

- One line per decision, with the reason.

## Change log

- <date>: what changed, why, and which sessions were told.
```
